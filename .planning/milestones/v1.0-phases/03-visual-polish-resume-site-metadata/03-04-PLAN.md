<task type="auto">
  <name>Task 1: Remove overlay gradient black bar (G-03-8)</name>
  <files>src/components/ProjectDetailsOverlay.vue</files>
  <action>In the `<style scoped>` block, in the `.dialog` rule, delete the `padding-bottom: 10px;` declaration — it is the only bottom-padding on `.dialog`. Leave every other `.dialog` property unchanged, including `background-color: #000000`, `margin: 20px`, and the `@media (min-width: 620px)` overrides. Do not touch `.dialog-content`, `h1.dialog-title`, or any other rule.

Why this is the fix (root cause confirmed in the debug session): the black-to-purple gradient (`linear-gradient(180deg, #000000 0%, #120818 45%, #2b123f 100%)`) lives only on the child `.dialog-content`. Because `.dialog` carries an extra 10px of bottom padding, the child's box stops 10px short of `.dialog`'s bottom edge, and `.dialog`'s own solid black paints that strip — the reported black bar. Removing the padding lets `.dialog-content` (and its gradient) extend to `.dialog`'s bottom edge, so the gradient's purple endpoint reaches the very bottom. `.dialog-content`'s own padding (20px mobile / 40px desktop) still keeps the Close button off the bottom edge, so no spacing is lost inside the content. This is a smaller, safer diff than moving the padding onto `.dialog-content` (which would clobber its 20px/40px shorthand).</action>

  </verify>
  <done>The `.dialog` rule no longer declares bottom padding; the `.dialog-content` gradient (linear-gradient still present per the grep) paints to the dialog's bottom edge; the overlay ends in purple with no black bar.</done>
