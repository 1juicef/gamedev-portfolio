<task type="auto">
  <name>Task 1: Add top spacing to the resume page (G-03-4)</name>
  <files>src/views/Resume.vue</files>
  <action>
The resume image renders flush against the header because `.resume-page` uses `align-items: flex-start` with no top spacing, and App.vue's `.main` has zero top padding on desktop. Fix scoped to Resume.vue only.

In the scoped `<style>` block, add `padding-top: 48px;` to the `.resume-page` rule (per G-03-4). Keep `align-items: flex-start` and `justify-content: center` as-is — the padding alone supplies the vertical breathing room. 48px matches the site's desktop side-padding rhythm; the value is a judgment call in the ~40-64px range and can be nudged if it reads too high or too low.

Do NOT touch `.main` padding in App.vue — that global rule is shared by all routes (per the gap's `missing` note). The single new property in Resume.vue's scoped block is the entire fix.
  </action>
  <verify>
    <automated>grep -n "padding-top" src/views/Resume.vue</automated>
    <human-check>Run `npm run serve`, visit /resume: the resume image now shows a clear vertical gap below the header instead of sitting jammed at the top. Other routes are unaffected.</human-check>
  </verify>
  <done>`.resume-page` in Resume.vue has `padding-top` set; the resume image renders with visible top breathing room; no global `.main` padding was changed.</done>
</task>

<task type="auto">
  <name>Task 2: Widen the sitewide content column (G-03-5)</name>
  <files>src/App.vue</files>
  <action>
On wide desktop viewports the fixed 1280px content cap leaves ~320px of dead space per side at 1920px, reading as excessive left/right margin on every page.

In the `@media only screen and (min-width: 620px)` block, in the `.main, .header, .footer` rule, change `max-width: 1280px;` to `max-width: 1600px;` (per G-03-5). Leave `margin: 0 auto;` and the `.main { padding: 0 48px 40px; }` rule unchanged.

This selector is shared by `.main`, `.header`, and `.footer`, and every view renders inside `.main`, so the change is sitewide by design — that is intended. 1600px leaves ~160px/side at 1920px (down from ~320px) while not stretching content edge-to-edge on ultrawide. The value is tunable in the 1440-1600px range if 1600px reads too wide on the timeline.
  </action>
  <verify>
    <automated>grep -n "max-width: 1600px" src/App.vue</automated>
    <human-check>Run `npm run serve` on a >=1440px viewport and check every route (/game-projects, /other-projects, /resume, /contact): the content column reads balanced, not narrow-and-centered with heavy dead space. Header and footer stay aligned with the main column width.</human-check>
  </verify>
  <done>The `.main, .header, .footer` max-width at the desktop breakpoint is 1600px; content columns read balanced across all routes with reduced left/right dead space.</done>
</task>
