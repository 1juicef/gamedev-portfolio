<current_state_findings>
Findings from reading the real files — the executor does NOT need to re-derive these.

**Approach decision (already made — do not re-litigate).** Headless Chrome `--print-to-pdf` against a locally-served production build, driven by a committed Node script. Rejected alternatives: a new PDF npm dependency (puppeteer/pdfkit — heavyweight, and puppeteer would download a second Chromium when a system Chrome already exists); `file://` on `dist/index.html` (breaks — the build emits root-relative `/js/…`, `/css/…`, `/fonts/…` paths that do not resolve under `file://`); a bespoke separate print-template page (more code and a second copy of the resume content to keep in sync, for no gain over a print stylesheet).

**Environment (verified this session):**
- Chrome present at `C:\Program Files\Google\Chrome\Application\chrome.exe`, version **151.0.7922.76** — modern, so a bare `--headless` is already the new headless and `--no-pdf-header-footer` is supported.
- Node **v22.23.1** — `http`, `zlib`, `fs`, `os` builtins are all that the exporter needs. No new dependency is required or permitted.
- Invoking `chrome --version` in this environment printed `Opening in existing browser session.` — it attached to the user's running Chrome instead of answering. **The exporter must pass its own `--user-data-dir` pointing at a fresh temp dir**, or it risks the same attach-and-do-nothing behaviour.

**Build/serve facts:**
- `package.json` scripts already wrap `NODE_OPTIONS=--openssl-legacy-provider` via `cross-env`, so plain `npm run build` works — do not set the env var manually.
- There is **no** `vue.config.js`, so `publicPath` is the default `/` and build output goes to `dist/`.
- `/dist` is gitignored. `public/` is copied verbatim into `dist/` at build time.
- `scripts/convert-media.js` is the precedent for dev-machine tooling in this repo: `#!/usr/bin/env node`, `"use strict"`, CommonJS, 4-space indent, `execFile` with an argument array (never a concatenated shell string). Match it.

**Router is hash mode** (`src/router/index.ts` constructs `new VueRouter({ routes })` with no `mode`), so the resume URL is `http://127.0.0.1:<port>/#/resume`, and relative asset hrefs resolve against `/`.

**Page chrome that must be suppressed for print** (exact selectors, confirmed in the templates):
- `App.vue` renders `<Header />` → root `div.header` (containing `div.nav-bar`, `img.header-guy`), then `div.main`, then `<Footer />` → root `div.footer`.
- `Resume.vue` renders `a.download-button` (line 10) and an `h1` reading "Resume".
- `ProjectDetailsOverlay.vue` is `v-if="visible"` so it is absent when closed, but its `div.overlay` / `div.dialog` roots should be hidden defensively.

**Screen styling that fights paper** (all in `App.vue`'s global block unless noted):
- `html, body` carry a dark `linear-gradient` with `background-attachment: fixed`.
- `#app` sets `color: @textColor` (light), `font-size: 1.1em`, `line-height: 1.6em`, and **`text-align: justify`** — justified body text prints with visible rivers and must be reset to left.
- `a { opacity: 0.5 }` globally, and `Resume.vue` leans on `opacity` (0.5–0.9) for de-emphasis throughout. On white paper those become washed-out grey; print must set `opacity: 1` and express hierarchy with colour instead.
- `.main` has `max-width: 1600px` and `padding: 0 48px 40px` at ≥620px.
- `.resume-page` has `max-width: 900px; margin: 0 auto`.

**Media-query behaviour in print:** Chrome lays print pages out at paper width (~816 CSS px for A4/Letter minus margins), so the existing `min-width: 620px` desktop rules — including `.resume-columns { grid-template-columns: 1.3fr 1fr }` — already apply in the PDF. The print block should still state the grid explicitly so it does not depend on that coincidence.

**Font Awesome is CDN-loaded** from `stackpath.bootstrapcdn.com` in `public/index.html`. That host is unreliable, so `i.fa` icons may render as blank boxes or nothing at all. For a job-application PDF, tofu boxes are worse than no icons — and hiding them also makes the export reproducible offline. Print hides `i.fa`.

**Asset path choice:** `public/downloads/Josef-Ubaka-Resume.pdf`. Not `public/img/` (it is not an image); not `public/resume/` (avoids any confusion with the `/resume` route); not `public/d/` (that is a 0-byte `some-file.pdf` leftover from the upstream fork template).

**`public/img/actualResume.png` stays on disk.** It is the user's own artifact and a grep proved `src/views/Resume.vue` line 10 is its only reference, so orphaning it is harmless. Deleting user assets is not what was asked — just note it as orphaned in the SUMMARY.

**3. Create `scripts/export-resume-pdf.js`** — CommonJS, `#!/usr/bin/env node`, `"use strict"`, 4-space indent, matching `scripts/convert-media.js` in shape and comment style. Zero new dependencies: `fs`, `os`, `path`, `http`, `url`, `child_process`, `util` only. Structure:

- Constants: repo root as `path.join(__dirname, "..")`; `DIST` = `<root>/dist`; `OUT_DIR` = `<root>/public/downloads`; `OUT_PDF` = `<OUT_DIR>/Josef-Ubaka-Resume.pdf`; the route fragment `/#/resume`.
- Fail fast if `<DIST>/index.html` is absent, with a message telling the operator to run `npm run build` first. The exporter reads a build, it does not produce one.
- `resolveChrome()` — return `process.env.CHROME_PATH` when set and existing; otherwise the first path that exists among `C:\Program Files\Google\Chrome\Application\chrome.exe`, `C:\Program Files (x86)\Google\Chrome\Application\chrome.exe`, `<LOCALAPPDATA>\Google\Chrome\Application\chrome.exe`, `/usr/bin/google-chrome`, `/usr/bin/chromium`. Throw a message naming the `CHROME_PATH` override if none resolve.
- A local static server over `DIST` via `http.createServer`, bound to `127.0.0.1` on port `0` (ephemeral; read the real port back off `server.address()`). Handling: take only the pathname (drop query and fragment), `decodeURIComponent` it, map `/` to `index.html`, resolve the result against `DIST`, and **reject with 403 anything whose resolved path is not inside `DIST`** — a startsWith check against the dist root plus a separator, so `..` sequences cannot escape. 404 on a missing file. A small extension-to-content-type map covering `.html .js .css .map .ttf .woff2 .png .jpg .jpeg .webp .gif .mp4 .svg .ico .json .pdf`, defaulting to `application/octet-stream`.
- Create `OUT_DIR` with `fs.mkdirSync(…, { recursive: true })` before printing — Chrome will not create the directory itself.
- A throwaway Chrome profile via `fs.mkdtempSync(path.join(os.tmpdir(), "resume-pdf-"))`, so the run cannot attach to the operator's already-open Chrome.
- Launch Chrome through `promisify(execFile)` with an **argument array**, never a shell string. Arguments, in order: `--headless`, `--disable-gpu`, `--no-first-run`, `--no-default-browser-check`, `--disable-extensions`, `--user-data-dir=<temp profile>`, `--virtual-time-budget=20000` (lets the lazy-loaded route chunk, the webfonts and the Vue render settle), `--run-all-compositor-stages-before-draw`, `--no-pdf-header-footer`, `--print-to-pdf=<OUT_PDF>`, then the URL `http://127.0.0.1:<port>/#/resume` last. Chrome exits by itself once the PDF is written. If a Chrome build ever rejects the bare flag, `--headless=new` is the documented substitute — note that in a comment.
- Post-run assertions, each throwing a specific message: the output file exists; its first five bytes are the PDF magic; its byte length is greater than 20000 and less than 5000000. Then log a single success line containing the byte count and the output path.
- Close the server and remove the temp profile dir (`fs.rmSync(…, { recursive: true, force: true })`) in a `finally`, so a failed print does not leave a listener or a profile behind. On any error, print it and exit non-zero.
