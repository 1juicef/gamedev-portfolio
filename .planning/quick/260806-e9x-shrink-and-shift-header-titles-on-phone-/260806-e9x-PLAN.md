<current_state_findings>
Findings from reading the real files — the executor does NOT need to re-derive these:

**Header.vue** — there is no site title element. The only text in `.header` is the four nav labels, rendered twice by a `v-if="isOnePage"` split:
- one-page routes (`/` and `/one-page`) render `<button class="nav-link">` elements
- all other routes render `<router-link>` anchors

Both are styled by the shared `a, .nav-link` selector, and `.nav-link` declares `font-size: inherit`, so a `font-size` set on `.nav-bar` cascades to both variants. Labels are uppercased via `text-transform` and carry `white-space: nowrap`, so they cannot break mid-word — they wrap as whole labels onto a second line.

Relevant existing rules:
- `.nav-bar { text-align: right; padding: 20px; line-height: 3em; }`
- `a, .nav-link { margin-left: 15px; margin-right: 15px; padding-bottom: 8px; }`
- `@media only screen and (min-width: 620px)` block → desktop max-width/centering (do not touch)
- `@media only screen and (max-width: 620px)` block → already overrides `.nav-bar` line-height to `2em`, `a, .nav-link` margins to `9px`, and `.header-guy` sizing. **This is the block to extend.**

No explicit `font-size` is set anywhere in Header.vue, so the labels currently inherit `#app { font-size: 1.1em }` from App.vue (~17.6px). Because `text-align: right` governs `.nav-bar`, adding `padding-right` is what shifts the label block leftward, away from the screen edge.

**Footer.vue** — the `.right` div currently holds a sentence combining an address anchor and a `/contact` router-link. The `.left` div ("Portfolio by Juicef" + mascot) is the tone reference and must stay untouched.
</current_state_findings>
