<key_facts>
Established before planning — do not re-derive:

- `ProjectData.accentColor` is `#6C3BAA` for all four live timeline projects and `#E08E32` for `cpp-sokoban` (the hidden WIP project). `wipProject` currently returns `undefined`, so the WIP block does not render, but its markup is identical to a timeline row and must receive the same treatment so it is correct when un-hidden.
- Contrast math, already computed: white on `#6C3BAA` is 7.4:1 (passes AA), white on `#E08E32` is 2.6:1 (fails AA). Therefore the cue must NOT use accent-as-fill with white text. Design is hue-agnostic: dark translucent fill, white label, accent used for border, glow, and the arrow.
- Vue 2.6 supports CSS custom properties in `:style` bindings (`web/runtime/modules/style.js` routes any `--` prefixed key through `el.style.setProperty`). This is the sanctioned wiring mechanism.
- Repo precedent from quick task 260726-nkb: a unicode triangle glyph was replaced with a CSS-drawn triangle because of mobile rendering problems. Draw the arrow in CSS; do not introduce a glyph.
- `.lazy-video-thumb` lives inside the `LazyVideoThumbnail` child component with its own scoped styles. Do not reach into it with a deep selector — style `.project-image-button` itself, which the `display: block` video fills exactly.
- iOS Safari only applies `:active` when the element has `cursor: pointer` or a touch listener. Both `.project-image-button` and `.project-title-link` already set `cursor: pointer`, so no JS listener is needed.
- There is no test suite in this repo. `npm run lint` is the only automated gate; structural greps carry the rest.
</key_facts>

<task type="tracer">
  <name>Task 1: Always-visible accent-tied "View Details" cue on every card</name>
  <files>src/views/GameProjects.vue</files>
  <action>
Wire one project's accent colour from the data layer through to a rendered, always-visible cue, then apply the same wiring to every card.

Template: on the `<section class="project-row">` inside the `v-for`, add a style binding setting the custom property `--project-accent` to `project.accentColor`. Add the identical binding to the WIP `.project-row` div, sourced from `wipProject.accentColor`. Binding at the row level (not the button) is deliberate: both the image button and the title button are descendants and can read it.

Inside each `.project-image-button` (timeline and WIP), after the `LazyVideoThumbnail`, add a decorative `<span class="project-cue" aria-hidden="true">` containing the label text `View Details` wrapped in its own `<span class="project-cue-label">`, plus an empty `<span class="project-cue-arrow"></span>`. Mark the outer span `aria-hidden` because the button already carries an explicit `aria-label`, which overrides descendant text for the accessible name — the cue is purely visual.

Scoped styles: give `.project-image-button` `position: relative` so it anchors the cue, and add `touch-action: manipulation` plus `-webkit-tap-highlight-color: transparent` to both `.project-image-button` and `.project-title-link` — the first removes the tap delay so Task 2's feedback feels instant, the second suppresses the browser's default grey flash that would otherwise fight the accent response.

Style `.project-cue` as an absolutely positioned pill at `bottom: 10px; right: 10px`, `display: inline-flex` with `align-items: center` and a small `gap`, `pointer-events: none`, `max-width: calc(100% - 20px)`, `white-space: nowrap`, `border-radius` around 999px, padding roughly `5px 10px`, `font-size: 0.72em`, uppercase with slight `letter-spacing`, colour `#ffffff`, background `rgba(0, 0, 0, 0.75)`. For the accent: `border: 2px solid` and `box-shadow: 0 0 12px -2px` both reading `var(--project-accent, #6C3BAA)`. Precede each of those two accent declarations with an identical declaration using the literal fallback colour so browsers without custom-property support still render a styled pill rather than dropping the declaration. The glow is what makes a dark purple accent legible against the dark page; the white-on-dark label is what keeps the text readable no matter what hue a future project uses.

Draw `.project-cue-arrow` as a right-pointing CSS triangle: zero width and height, `border-style: solid`, `border-width: 4px 0 4px 6px`, and `border-color` transparent on three sides with `var(--project-accent, #6C3BAA)` on the left edge — again preceded by a literal-colour fallback declaration. Do not use a glyph character.

At the mobile default width the swing-space card is constrained to 46% of the row, so confirm the pill's own width stays inside `max-width: calc(100% - 20px)` there rather than spilling past the thumbnail edge.

<task type="auto">
  <name>Task 2: Tap, focus, and desktop-hover response states</name>
  <files>src/views/GameProjects.vue</files>
  <action>
Add interaction states to the scoped style block, building out from the cue Task 1 proved.

Tap feedback on `.project-image-button:active`: `transform: scale(0.985)` and `box-shadow: 0 0 0 2px var(--project-accent, #6C3BAA)` (literal-colour fallback declaration first, as in Task 1). Because the button has no padding and the video is `display: block`, that ring traces the thumbnail edge exactly. Add `transition: transform 0.14s ease, box-shadow 0.14s ease` to the base `.project-image-button` rule so the ring fades rather than snapping.

Intensify the cue during the press with `.project-image-button:active .project-cue { filter: brightness(1.4); }` and a matching short `transition: filter` on the base `.project-cue` rule. Use `filter` rather than swapping the fill to the accent colour: brightening is hue-agnostic and preserves the white label's contrast in every state, whereas an accent fill would drop the orange WIP accent to 2.6:1.

Give `.project-title-link:active` a matching press by setting its `border-bottom-color` to `var(--project-accent, #6C3BAA)` (literal fallback first). Leave the existing pink `#f4cde6` hover/focus colours on `.project-title-link` and `.game-jam-link` untouched — that is the established hover language of the page and is out of scope here.

Close the existing keyboard gap: `.project-image-button:focus-visible` currently has no styling at all (the element sets `border: 0` and a transparent background). Give it the same accent ring the `:active` state uses, plus `outline: none` only because that ring replaces it.

Add a `@media (hover: hover) and (pointer: fine)` block for the desktop-only bonus: `.project-image-button:hover` gets `transform: scale(1.015)` and `.project-image-button:hover .project-cue` gets a stronger accent glow via a larger `box-shadow` spread. Gate on `pointer: fine` as well as `hover` so touch devices that report a coarse hover capability do not get stuck in a hover state after a tap.

Add a `@media (prefers-reduced-motion: reduce)` block that sets `transform: none` for the `:active` and `:hover` states and drops the transform transitions, leaving the colour and glow changes intact so the feedback still registers without motion.
